# Glossary

Project-specific terms used across the Question Bank Generator code and docs, with the file that defines or implements each one. The code is the source of truth: when a definition here disagrees with the code, the code wins. Numbers are the defaults in [`backend/app/core/config.py`](../backend/app/core/config.py) and can be overridden through `.env` (see [SETUP_AND_CONFIG.md](SETUP_AND_CONFIG.md)).

## Generation structure

| Term | Definition | Where |
| :--- | :--- | :--- |
| **Slot** | One position in a question set (index 0-4 in a 5-question job). A slot owns one question's drafting, review and replenishment attempts; its spend is tracked in the slot ledger. | [`workflow/slot_worker.py`](../backend/app/workflow/slot_worker.py), [`workflow/engine_layout.py`](../backend/app/workflow/engine_layout.py) |
| **Slot attempt / replenishment** | When a slot's draft is rejected or errors out, the slot worker drafts it again as a new attempt (`attempt > 0`) with a retry directive that forces a different paragraph, claim or variable. Delays between attempts are `SLOT_REPLENISH_DELAY_SECONDS` and `SLOT_ERROR_RETRY_DELAY_SECONDS`. | [`workflow/slot_worker.py`](../backend/app/workflow/slot_worker.py) |
| **Slot ledger (`SlotLedger`)** | Dataclass holding per-slot tokens, prompt/completion split, cost, usage breakdown and LLM call count, summed across every attempt of that slot. It feeds the per-slot LLM call budget and the SSE totals. | [`workflow/engine_layout.py`](../backend/app/workflow/engine_layout.py) |
| **LLM call budget** | Hard cap of `MAX_LLM_CALLS_PER_SLOT` (default 36, `0` disables) LLM calls per slot across drafts, dedup retries, regenerations, review and solve samples and replenishments. Checked by `llm_budget_exhausted`. | [`core/config.py`](../backend/app/core/config.py), [`workflow/review_loop.py`](../backend/app/workflow/review_loop.py) |
| **Slot / passage blueprint** | The fixed 5-question set layout for a shared passage: `CARS_PASSAGE_SET_BLUEPRINTS` and `SCIENCE_PASSAGE_SET_BLUEPRINTS`, one entry per slot with `skill`, `archetype`, `directive` and a passage excerpt anchor. | [`workflow/passage_blueprints.py`](../backend/app/workflow/passage_blueprints.py) |
| **Archetype** | The named question type of a blueprint slot. CARS: Central Claim / Main Thesis, Local Detail & Passage Evidence, Rhetorical Function / Author's Stance, Reasoning Beyond the Text (Novel Scenario Application), Reasoning Beyond the Text (Challenge / Weaken Assumptions). Science: Scientific Concept & Principle Foundation, Data / Figure & Graph Interpretation, Experimental Design & Methodological Rationale, Scientific Reasoning & Problem Solving / Downstream Mechanism, Novel Experimental Condition / Hypothesis Testing. | [`workflow/passage_blueprints.py`](../backend/app/workflow/passage_blueprints.py) |
| **Thematic angle** | A per-job scenario focus that keeps jobs in one batch from converging. Two sources exist: the curated per-section lists in `data/thematic_angles.py` (`batch_thematic_angle(job_number, req)` returns `Set #N: <angle>`) and the AI-native/deterministic angle planner in `agents/batch_planner.py` (`_build_deterministic_angles`, cached per batch). | [`data/thematic_angles.py`](../backend/app/data/thematic_angles.py), [`agents/batch_planner.py`](../backend/app/agents/batch_planner.py) |
| **Rotation pool / domain index** | On a replenishment attempt the worker swaps in a different application domain (CARS slot 4, `CARS_SLOT4_APPLICATION_DOMAINS`) or experimental condition (Science slot 5, `SCIENCE_SLOT5_EXPERIMENTAL_CONDITIONS`). `resolve_slot_domain_index(req, attempt)` returns an index in 0-9 derived from the thematic angle's `Set #N` (or a hash of the passage/batch/run id) plus the attempt number, modulo 10; both pools hold 10 entries. | [`workflow/passage_blueprints.py`](../backend/app/workflow/passage_blueprints.py), [`workflow/slot_worker.py`](../backend/app/workflow/slot_worker.py) |
| **Diversity context** | Prompt text appended to a slot's drafting request so it avoids traps and misconceptions its siblings already used; on replenishment it names a fresh trap from `ALT_TRAP_ROTATION`. | [`workflow/engine_layout.py`](../backend/app/workflow/engine_layout.py), [`agents/prompt_builder.py`](../backend/app/agents/prompt_builder.py) |
| **Job / set** | One unit of background batch work that produces one 5-question set (`QUESTIONS_PER_JOB = 5`). A 50-question batch is 10 jobs. The UI says "set"; the database table is `generation_jobs`. | [`services/batch_worker.py`](../backend/app/services/batch_worker.py), [`models/job.py`](../backend/app/models/job.py) |
| **Trial** | One execution attempt of a job. A job is limited to `MAX_JOB_TRIALS = 3` trials; manual retry or resume is refused with HTTP 400 once they are exhausted. Shown in the UI as `AUTO-RETRYING X/3`. | [`services/batch_worker.py`](../backend/app/services/batch_worker.py), [`services/batch_runner.py`](../backend/app/services/batch_runner.py) |
| **Refill cycle** | One pass of replenishing a batch that is short of its target (after duplicates are purged or jobs fall short). Capped at `MAX_REFILL_CYCLES = 3`. | [`services/batch_worker.py`](../backend/app/services/batch_worker.py), [`services/batch_runner.py`](../backend/app/services/batch_runner.py) |
| **Shared passage / `passage_mode`** | `single_passage`: all questions of a set are linked to one passage (shared stimulus, one `passage_id`). `independent`: standalone discrete questions with no passage. | [`schemas/workflow.py`](../backend/app/schemas/workflow.py) |
| **Batch** | A multi-question generation run made of jobs (`generation_batches`). Statuses are defined in `BatchStatus` / `JobStatus`. | [`schemas/status.py`](../backend/app/schemas/status.py), [`models/batch.py`](../backend/app/models/batch.py) |

## Agents and the quality pipeline

| Term | Definition | Where |
| :--- | :--- | :--- |
| **Generator / fused generator** | The drafting agent (node `fused_generator_node`). With the default `ALWAYS_INDEPENDENT_REVIEW=True` it produces the draft only. With `ALWAYS_INDEPENDENT_REVIEW=False` it runs in fused mode, drafting and self-scoring in one call, and a self-score above the threshold lets the independent review be skipped (`fused_self_passed`). | [`workflow/node_generator.py`](../backend/app/workflow/node_generator.py), [`agents/generator.py`](../backend/app/agents/generator.py) |
| **Reviewer** | Independent agent that scores a draft on the 100-point, four-pillar rubric. | [`agents/reviewer.py`](../backend/app/agents/reviewer.py), [MCAT_RUBRIC.md](MCAT_RUBRIC.md) |
| **Regenerator (Re-Generator)** | Remediation agent that repairs a draft using the reviewer's weaknesses. Logged as "Question Re-Generator"; the stage inspector in the UI labels it "Polish & Refine". | [`agents/regenerator.py`](../backend/app/agents/regenerator.py), [`workflow/node_reviewer.py`](../backend/app/workflow/node_reviewer.py) |
| **Blind solver** | Agent that answers the question without seeing the author's key or explanation. It samples `BLIND_SOLVER_SAMPLES` (default 2) option layouts (reversed, rotated), plus a tie-breaker only if they disagree. | [`agents/blind_solver.py`](../backend/app/agents/blind_solver.py) |
| **Majority vote** | The solver result requires a strict majority of samples on the author's key; a key mismatch or confidence below `BLIND_SOLVER_CONFIDENCE_THRESHOLD` (default 88) triggers remediation. | [`agents/blind_solver.py`](../backend/app/agents/blind_solver.py) |
| **Review loop** | The per-question loop: deterministic gate, then reviewer (and solver), then `route_after_review`, with regeneration in between. With `PARALLEL_REVIEW_AND_SOLVE=true` (default) reviewer and solver run concurrently. | [`workflow/review_loop.py`](../backend/app/workflow/review_loop.py) |
| **Deterministic gate / validator** | Free structural checks that run before any LLM review: four unique options A-D, valid key, forbidden dashes (auto-repaired), "all/none of the above", option-length spread, and so on. Blocking violations go to regeneration or rejection without a review call. | [`agents/validators.py`](../backend/app/agents/validators.py), [`workflow/review_loop.py`](../backend/app/workflow/review_loop.py) |
| **Quality gate / `route_after_review`** | Routing function returning `regenerator`, `reject`, `image_generator` or `finalize`. A score must be strictly above `PASSING_SCORE_THRESHOLD` (default 80, `config.passes_quality_gate`). Below it the draft is regenerated until `MAX_REGENERATION_ATTEMPTS` (default 3) is reached. | [`workflow/routes.py`](../backend/app/workflow/routes.py), [`core/config.py`](../backend/app/core/config.py) |
| **Score tiers** | Defined in `determine_question_status`: score > 80 is `ai_validated`; 70-80 inclusive (threshold minus 10 up to the threshold) is `batch_only` ("Good Quality", kept in the batch only); below 70 is `below_threshold`. While a batch is still generating, anything at or above 70 is `batch_only`. After the final attempt, a score of 70 or more is accepted into the batch; below 70 is rejected. | [`schemas/question.py`](../backend/app/schemas/question.py), [`workflow/routes.py`](../backend/app/workflow/routes.py) |
| **Question statuses** | The nine `QuestionStatus` values: `in_bank`, `ai_validated`, `batch_only`, `approved` (active) and `below_threshold`, `discarded`, `rejected_below_threshold`, `error`, `failed` (inactive). | [`schemas/question.py`](../backend/app/schemas/question.py) |
| **Fail closed / `QualityCheckUnavailableError`** | If the reviewer or blind solver cannot produce a trustworthy result, this error is raised and the item is never accepted unchecked. | [`agents/base.py`](../backend/app/agents/base.py), [`agents/reviewer.py`](../backend/app/agents/reviewer.py), [`agents/blind_solver.py`](../backend/app/agents/blind_solver.py) |
| **Offline mode** | `OFFLINE_MODE=True` allows mock/heuristic fixtures when no credentials exist (`LLMNotConfiguredError`). Off by default, so a missing key fails loudly. The test suite turns it on. | [`agents/base.py`](../backend/app/agents/base.py), [`agents/mock_fixtures.py`](../backend/app/agents/mock_fixtures.py) |
| **Stage outcomes** | JSON map saved on each question recording what each pipeline stage produced (for example `drafting`, `option_symmetry`, review and audit results). The UI shows it in the stage inspector. | [`workflow/node_generator.py`](../backend/app/workflow/node_generator.py), [`StageJsonInspector.jsx`](../frontend/src/components/question/StageJsonInspector.jsx) |

## Distractor and option engineering

| Term | Definition | Where |
| :--- | :--- | :--- |
| **Primary trap** | The dominant cognitive error a question is built to elicit, stored in `primary_trap`. The valid ids come from the `primary_trap` list in the taxonomy JSON (25 ids such as `CONCEPT_CONFUSION`, `SCOPE_SHIFT`), with a default of automatic selection by the generator. | [`schemas/mcat.py`](../backend/app/schemas/mcat.py), [`data/mcat_dependent_taxonomy.json`](../backend/app/data/mcat_dependent_taxonomy.json) |
| **Likely mistake pattern** | The student misconception the item targets (`likely_mistake_pattern`), either set by the educator or diagnosed by the generator. | [`agents/prompt_builder.py`](../backend/app/agents/prompt_builder.py), [`agents/draft_parser.py`](../backend/app/agents/draft_parser.py) |
| **`ALT_TRAP_ROTATION`** | Fixed 8-trap sequence used to re-seed a trap on replenishment and on anti-collision regeneration so the retry tests something different. | [`schemas/mcat.py`](../backend/app/schemas/mcat.py), [`workflow/engine_layout.py`](../backend/app/workflow/engine_layout.py) |
| **Option symmetry** | Length parity across the four options so the answer cannot be guessed by length. The allowed spread (longest minus shortest, in words) is `max(3, ceil(0.20 x mean option length))`. `calculate_option_symmetry` scores the longest/shortest ratio in bands (ideal up to 1.15, balanced up to 1.25, moderate up to 1.40). | [`agents/standards.py`](../backend/app/agents/standards.py), [`agents/option_balancer.py`](../backend/app/agents/option_balancer.py) |

## Deduplication and retrieval

| Term | Definition | Where |
| :--- | :--- | :--- |
| **Hard duplicate** | Similarity at or above `DUPLICATE_HARD_THRESHOLD` (default 0.75); used by the engine, batch clustering and resolution. The on-demand duplicate check endpoint uses the stricter `DUPLICATE_API_THRESHOLD` (default 0.80). | [`core/config.py`](../backend/app/core/config.py), [`services/deduplication.py`](../backend/app/services/deduplication.py) |
| **Soft warning** | Similarity from `DUPLICATE_SOFT_THRESHOLD` (default 0.60) up to the hard threshold: flagged as a variety warning, not rejected. | [`workflow/dedup_inflight.py`](../backend/app/workflow/dedup_inflight.py) |
| **Anti-collision loop** | After drafting, the draft is compared with the database, siblings and in-flight drafts; on a hard duplicate the generator is re-prompted with an avoidance directive and a different trap, up to `DEDUP_REGEN_MAX_RETRIES`. | [`workflow/dedup_inflight.py`](../backend/app/workflow/dedup_inflight.py) |
| **In-flight draft** | A draft produced by a sibling slot of the same batch that is not yet saved; kept in a process-local registry so slots can detect collisions with each other. | [`workflow/dedup_inflight.py`](../backend/app/workflow/dedup_inflight.py) |
| **RAG exemplar** | A high-scoring existing question (score at or above `RAG_EXEMPLAR_MIN_SCORE`, default 90) retrieved by pgvector similarity and shown to the generator as a few-shot example. | [`services/rag.py`](../backend/app/services/rag.py) |
| **Avoidance stem** | A nearest-neighbor existing question stem listed in the generation prompt so the new question avoids it. | [`services/rag.py`](../backend/app/services/rag.py) |
| **Duplicate cluster** | A group of batch questions whose pairwise similarity reaches the threshold; resolution keeps a leader and archives (default) or hard-deletes the rest. Endpoints: `GET /api/batches/{batch_id}/duplicate-clusters` and `POST /api/batches/{batch_id}/resolve-duplicates`. | [`services/dedup_clustering.py`](../backend/app/services/dedup_clustering.py), [`services/batch_resolution.py`](../backend/app/services/batch_resolution.py) |

## Application features

| Term | Definition | Where |
| :--- | :--- | :--- |
| **Copilot** | The AI assistance tools behind `/api/ai/enhance-instructions`, `/api/ai/refine-question`, `/api/ai/audit-passage` and `/api/ai/study-guide`, surfaced in the UI by the copilot strip on question cards. The passage audit is a local readability computation (`services/readability.py`), not an LLM call. | [`services/ai_copilot.py`](../backend/app/services/ai_copilot.py), [`api/v1/ai.py`](../backend/app/api/v1/ai.py), [`QuestionCopilotStrip.jsx`](../frontend/src/components/question/QuestionCopilotStrip.jsx) |
| **Study guide** | A Markdown study guide synthesized from selected questions by the `/api/ai/study-guide` endpoint; the export dialog can copy or download it and download an Anki-compatible TSV deck. | [`api/v1/ai.py`](../backend/app/api/v1/ai.py), [`StudyGuideExportPane.jsx`](../frontend/src/components/modals/StudyGuideExportPane.jsx) |
| **Editorial desk** | The Passage Bank screen area where an educator edits a reading passage, runs the readability check and reviews linked questions. | [`PassageEditorialDesk.jsx`](../frontend/src/components/passage/PassageEditorialDesk.jsx) |
| **Soft delete** | Deleting sets `is_deleted = true` and keeps batch progress counts intact; restore through `POST /api/questions/{id}/restore`. | [`repositories/_filters.py`](../backend/app/repositories/_filters.py), [`docs/API.md`](API.md) |
| **Duplicate override** | An educator can approve a flagged duplicate (`is_duplicate_override`, `overridden_at`). In the web app it is the **Override and approve** action on the duplicate alert bar or compare dialog (a direct click followed by a toast). | [`models/question.py`](../backend/app/models/question.py), [`useDuplicateOverride.js`](../frontend/src/hooks/useDuplicateOverride.js) |
| **Similar vs hard duplicate (UI)** | The API only flags hard duplicates (`is_duplicate`, similarity at or above 0.75). The web app also shows **Similar** for an unflagged question at or above the soft threshold (`DUPLICATE_SOFT_THRESHOLD` = 0.6, mirrored in `constants/mcat.js`); levels are `high`, `similar`, `overridden`, `none`. | [`duplicateHelpers.js`](../frontend/src/utils/duplicateHelpers.js) |
| **Duplicate risk badge / compare dialog** | The pill (`Duplicate Risk (NN%)`, `Similar (NN%)`, `Overridden`) on review-queue cards, batch question items and bank rows, and the side-by-side dialog that shows the question beside the original it matched. | [`components/duplicates/`](../frontend/src/components/duplicates/) |
| **Batch duplicate audit** | On-demand **Check duplicates** / **Resolve duplicates** panel in a batch card; resolving archives (recoverable) and shows how many questions the batch is now short of its target. | [`BatchDuplicateAudit.jsx`](../frontend/src/components/batch/BatchDuplicateAudit.jsx) |
| **Review queue shortcuts** | `A` saves the active review card to the bank (a hard unoverridden duplicate opens the compare dialog instead) and `D` discards it through the confirmation modal; ignored while typing, with a modal open, with modifier keys or on key repeat. | [`useKeyboardShortcuts.js`](../frontend/src/hooks/useKeyboardShortcuts.js) |
| **Reserved statuses** | `approved`, `rejected_below_threshold`, `error` and `failed` are allowed by the database CHECK constraint and the `QuestionStatus` enum but are never persisted by the pipeline. | [`schemas/question.py`](../backend/app/schemas/question.py) |
